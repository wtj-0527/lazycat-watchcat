# P4 生产校准与自动巡检

## nasw 数据校准（2026-08-23）

| 指标 | 宿主机基准 | WatchCat 数据源 | 结论 |
|---|---:|---|---|
| 1 分钟负载 | `/proc/loadavg` | 应用内共享 `/proc/loadavg` | 可用 |
| 内存总量/可用量 | `/proc/meminfo` | 应用内共享 `/proc/meminfo` | 可用 |
| LazyCat 数据池 | `/lzcsys/data` 使用率 89% | `/lzcapp/var` 所在文件系统 | 可用，语义已由“根文件系统”校准为“LazyCat data” |
| 网络累计流量 | `/proc/net/dev` | 应用网络命名空间 | 可用，但仅代表 WatchCat 应用网络 |
| SMART/NVMe | 宿主机 `smartctl` 可读 | 应用未映射宿主机块设备 | 不可用，界面必须明确显示，不得推断健康 |
| Btrfs 物理池 | 宿主机 `btrfs filesystem show` 可读 | 应用未映射宿主机挂载 | 不可用，界面必须明确显示 |
| LPK Runtime | 宿主机运行时可见 | 尚无稳定只读状态源 | 不可用，界面必须明确显示 |

## 自动巡检策略

- 每日 03:00 执行 `scheduled-daily`。
- 每周日 04:00 执行 `scheduled-weekly`。
- 同一自然日/ISO 周只执行一次，状态持久化在 SQLite。
- 应用启动后必须先收到本次进程产生的新鲜指标，调度器才允许运行，避免升级窗口产生“空数据健康”报告。
- 周日 04:00 之后首次启动时，周检覆盖当天补偿日检，避免同一时刻生成两份重复报告。
- 单次失败最多重试 3 次，采用 1 秒、2 秒退避。
- 报告保存设备快照、告警、数据时间、SHA-256 证据摘要和相对上一次报告的变化。
- 巡检出现 Critical 时进入 LazyCat 系统通知持久队列。

## 数据可信度规则

- 高级能力未授权或数据源不存在时标记为 `unavailable`。
- 已配置但执行失败时标记为 `degraded` 并保存具体错误。
- 只有实际采集成功才标记为 `available`。
- 超过 10 分钟的指标不参与当前告警计算。
- 旧版无标签的本机文件系统序列在升级时清理，避免错误告警残留。
